先看這裡

兩個功能，請用兩個練習用 LINE 官方帳號

這份講義提供兩套獨立程式。一個 Messaging API Channel 只能設定一個 Webhook URL；如果把第二個網址貼到同一個 Channel，第一個功能就收不到訊息。

  • 只做一個小幫手：準備一個練習帳號即可。
  • 兩個都要保留：分別建立「行事曆小幫手」與「單詞小幫手」兩個練習帳號。
  • 不要拿學校或單位正在使用的正式官方帳號做課堂測試。

四個名詞先分清楚

設定時最常搞混的東西

LINE 官方帳號
學生實際加入好友、傳訊息的帳號。
Messaging API
讓自己的程式可以接收並回覆 LINE 訊息。
Channel access token
程式呼叫 LINE API 的密碼。不可公開，也不是 Channel secret。
Webhook URL
LINE 把訊息送到 Apps Script 的 /exec 網址。
綁定碼
只有行事曆版會產生；12 碼、10 分鐘有效，用來授權某個 LINE 使用者。
「綁定雲端」
這是舊版雲端硬碟搜尋指令，本課不使用。

路線 A

LINE × GOOGLE CALENDAR

行事曆小幫手：從官方帳號到新增測試活動

只接受私人聊天。訊息先變成 10 分鐘有效的草稿，輸入確認碼後才會真的新增活動。

01

建立練習用 LINE 官方帳號

  1. 開啟 LINE Official Account Manager，點「免費開設帳號」。
  2. 登入 LINE Business ID，填寫帳號名稱、類別與聯絡資料。
  3. 建議名稱：行事曆小幫手－暱稱或座號。
  4. 課堂練習使用未認證帳號即可；不要使用單位的正式官方帳號。

完成後會看到：自己的官方帳號管理後台。

02

啟用 Messaging API，取得 Token

  1. 進入剛建立的官方帳號，點右上角「設定」→「Messaging API」。
  2. 點「啟用 Messaging API」，建立或選擇自己的練習用 Provider。
  3. 開啟 LINE Developers Console，進入剛才的 Messaging API Channel。
  4. 在「Messaging API」分頁找到 Channel access token (long-lived)，點 Issue／發行並複製。

先確認再選：Messaging API 啟用後不能更換或解除 Provider。不可選老師、其他組別或單位正式使用的 Provider。Channel secret 不是 Token；不要把 Token 貼到 Code.gs、班群、GitHub 或作業截圖。

03

建立 Google 試算表與兩個指令碼檔案

  1. 建立空白 Google 試算表，命名為「LINE 行事曆小幫手－暱稱或座號」。
  2. 點「擴充功能」→「Apps Script」。
  3. 用下載的行事曆版 Code.gs 取代原本內容。
  4. 按檔案清單旁的「＋」→「指令碼」，建立 LineCalendar.gs，貼入第二份程式。
  5. 按儲存。

完成後會看到：左側檔案清單同時有 Code.gs 與 LineCalendar.gs。

04

把 Token 存到 Script Properties，設定台北時區

  1. Apps Script 左側點「專案設定」。
  2. 在「指令碼屬性」新增：名稱 LINE_TOKEN，值貼上自己的 Channel access token。
  3. 同一頁把專案時區設為 Asia/Taipei。
  4. 開啟 Google Calendar「設定」→「時區」，也確認為台北。

不要把 Token 寫在程式碼的引號裡。若曾公開過 Token，請回 LINE Developers 重新發行，再更新 LINE_TOKEN。

05

部署成 Web App

  1. 右上角「部署」→「新增部署作業」。
  2. 類型選「網頁應用程式」。
  3. 「執行身分」選我；「誰可以存取」選所有人／任何人，不必登入。
  4. 完成 Google 授權，複製以 /exec 結尾的網址。
  5. 用無痕視窗開啟網址，確認看到「LINE 行事曆小幫手運作中」。

判斷：若無痕視窗要求登入，表示存取權沒有開對，先回部署設定修正。

06

把 /exec 網址填到 LINE Webhook

  1. 回到 LINE Developers Console 的 Messaging API 分頁。
  2. 在 Webhook URL 貼上純 /exec 網址，不要再加其他文字。
  3. 點 Verify；看到 Success 後，開啟 Use webhook。
  4. 回 LINE Official Account Manager 的回應設定，測試期間先停用內建自動回應與歡迎訊息。
  5. 掃描 QR Code，把官方帳號加為好友。

Verify 成功只代表網址能收到測試請求；仍要實際傳訊息，才能確認 Token 與 Calendar 功能。

07

設定並綁定自己的 Google 行事曆

  1. 回到試算表並重新整理頁面。
  2. 點上方「🗓️ LINE 行事曆小幫手」→「設定 LINE 行事曆」。
  3. 留空使用主要行事曆，或貼上自己擁有的 Calendar ID。
  4. 畫面會顯示 12 碼一次性綁定碼。
  5. 10 分鐘內私訊：綁定行事曆 A1B2C3D4E5F6，把範例代碼換成畫面上的代碼。

完成後會收到：「LINE 行事曆綁定完成」。綁定碼用過就失效。

01

建立第二個練習用 LINE 官方帳號

  1. 開啟 LINE Official Account Manager，再建立一個官方帳號。
  2. 建議名稱：單詞小幫手－暱稱或座號。
  3. 如果你只做單詞路線，這就是今天唯一需要的練習帳號。

02

啟用 Messaging API，取得這個帳號自己的 Token

  1. 在官方帳號後台點「設定」→「Messaging API」→「啟用 Messaging API」。
  2. 選擇自己的練習用 Provider，完成條款確認。
  3. 到 LINE Developers Console 開啟單詞小幫手的 Channel。
  4. 在 Messaging API 分頁發行 Channel access token (long-lived)。

Provider 選定後不能更換或解除，不可選老師、其他組別或單位正式使用的 Provider。每個 Channel 的 Token 與 Webhook 要成對；貼到另一個帳號的 Token，即使 Verify 成功也可能不回覆。

03

把 Excel 詞表轉成 Google 試算表

  1. 到原住民族語學習詞表系統的「資源下載」，選擇單一語別的太魯閣語，下載 2026 年公告版 Excel。
  2. 把 Excel 上傳 Google Drive，用 Google 試算表開啟，再點「檔案」→「另存為 Google 試算表」。
  3. 在最左側插入新的 A 欄，標題填「啟用」；要讓 LINE 查到的資料列填「是」，原本七欄會右移成 B～H。
  4. 確認下方工作表名稱是 單詞列表，第一列依序為：啟用、序號、編號、中文、族語、備註、級別、類別。
  5. 把 C 欄「編號」設為純文字，避免 01-01 變成日期。

完成後會看到：原生 Google 試算表，而不是仍顯示 .xlsx 的 Office 編輯模式。

06

  1. 回到 Google 試算表並重新整理。
  2. 點「📖 LINE 單詞小幫手」→「初始化／檢查單詞列表」。
  3. 確認畫面回報的可查詞條數量正確。

為什麼要初始化：Web App 執行時沒有「目前開啟的試算表」，程式會把這份試算表 ID 存成 WORD_SHEET_ID，之後依 ID 開啟詞庫。

常見錯誤與最短修正路線

試算表看不到「擴充功能」

檔案可能仍是 .xlsx。先點「檔案」→「另存為 Google 試算表」，再從新檔案開 Apps Script。

/exec 網址要求登入

Web App 存取權沒有設成「所有人／任何人，不必登入」。回「部署」→「管理部署作業」檢查。

Google 顯示「這個應用程式未經驗證」

只有在這份程式是你自己建立、已閱讀內容，而且來源確定時，才依畫面展開「進階」並繼續授權。若專案來自陌生人、內容不確定或要求超出課程的權限，立刻停止並請老師檢查。

部署時看不到「所有人／任何人」

學校或單位的 Google Workspace 管理員可能禁止公開 Web App。請改用老師允許的個人練習帳號，或請管理員確認政策；不要嘗試繞過單位限制。

Verify 成功，但 LINE 沒有回覆

依序檢查 Use webhook、Script Property 的 LINE_TOKEN，以及 Token 和 Webhook 是否來自同一個 Channel，再看 Apps Script 執行記錄。

LINE 同時收到兩則回答

LINE 官方帳號的內建自動回應或歡迎訊息仍開啟。測試期間先停用，讓 Webhook 單獨回答。

修改程式後，LINE 還是舊行為

程式碼變更要到「管理部署作業」編輯部署並建立新版本。只有修改單詞表資料不必重新部署。

單詞編號 01-01 變成日期

先把 C 欄「編號」設成純文字，再重新輸入 01-01。

行事曆只收到草稿，沒有新增活動

這是安全設計。請檢查草稿內容，再輸入「確認行事曆＋畫面顯示的確認碼」。

行事曆日期或時間不正確

Apps Script 專案與 Google Calendar 的時區都要設為 Asia/Taipei，再重新建立一筆測試活動。

第二個功能設定後，第一個功能壞了

你可能把同一個 Channel 的 Webhook URL 換掉了。兩套獨立程式請使用兩個練習官方帳號。

安全、資料與族語責任

課堂能成功，不代表可以直接拿去正式營運

分清楚哪些是祕密

Token 與 Channel secret 是憑證，絕對不能公開；綁定碼雖然短暫有效，也不要分享。/exec 網址不是密碼，但本課原型仍不要主動貼到公開頁面。

只用測試資料

行事曆不要輸入正式工作、賓客、個資或敏感排程；單詞表不要放學生個資或成績。

知道原型限制

純 Apps Script Web App 無法可靠讀取 LINE 的簽章標頭，因此這是教學原型，不適合承載敏感資料或正式公開服務。

詞料要人工確認

程式只負責查詢，不代表拼寫、語意、級別或分類必然正確。本課範例指向語發基金會 2026 年公告版；使用與改作仍須遵守官方標示，並由族語教師或資料權責者確認，不可混用不同族群詞表。

A / 行事曆組
  1. 建立一筆未來日期的虛構測試活動。
  2. 先截 LINE 草稿，再完成確認。
  3. 截取 Google Calendar 中唯一一筆完成活動。
  4. 用 100 字說明為什麼需要第二次確認。
B / 單詞組
  1. 新增 5 筆由老師確認的詞條。
  2. 分別用族語、中文、編號查詢。
  3. 將其中一筆 A 欄改成「否」或清空，證明它不再被查到。
  4. 附上詞料來源與授權說明。
