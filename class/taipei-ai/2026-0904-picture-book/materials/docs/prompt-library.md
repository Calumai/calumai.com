# A. NotebookLM：查、拆、對

## N-CLASS｜課堂快速事實包（當堂核心只用這一組）

```text
你是繪本來源管理員。只使用我目前勾選的來源，建立一份可交給作者確認的「故事事實包」。

請輸出五區：
1. 來源表：來源 ID、名稱、類型、可支持什麼、文件中記錄的授權／審訂狀態、引用。
2. 事件表：順序、人物、動作、原因、結果、引用。
3. 不可改寫：鎖定名稱、原文、譯文、關鍵因果與適用範圍，逐項附引用。
4. 待確認：來源衝突、資料缺口、文化／語言／權利問題，以及需要誰確認。
5. 創作空間：來源沒有規定、但必須由作者決定的欄位。

規則：
- 來源沒有寫到就填「來源未記錄」，不得用常識補完。
- 不自行裁決衝突、授權、族語、服飾、祭儀、歷史或身分。
- 不把一張人物或服飾照片泛化成整個群體、年代、性別或場合。
- 每個重要主張都要有引用；找不到引用就不能放進「已確認」。
- 最後輸出 Gate 1 清單：可繼續／需去識別／需真人確認／不得上傳或公開。
```

課堂中先用這一組完成 `source-pack.md`，由人通過 Gate 1，再把核准內容交給聊天機器人 C01。以下 N01–N08 是拆開練習或課後進階，不需要在 20 分鐘內全部操作。

## N00｜筆記本共用規則

建議在本次繪本筆記本的第一輪先貼：

```text
你是本繪本專案的來源研究助手。

工作規則：
1. 只根據我目前勾選的來源回答。
2. 每個重要事實、引文、文化或語言說明都要附來源引用。
3. 來源沒有寫到，就標示「待確認」或「來源未記錄」，不得用常識補完。
4. 來源互相衝突時，並列各自說法與引用，不替我裁決。
5. 明確分開「來源支持」、「AI 整理」與「可供作者創作的空白」。
6. 不判定授權、族語、服飾、祭儀或歷史一定正確；把這些項目交由真人確認。
7. 不把一張人物或服飾照片泛化成整個族群、性別、年代或場合的標準。

如果理解，先只回覆你將遵守以上規則，不要開始改寫故事。
```

## N01｜來源盤點表

```text
你是繪本來源管理員。只使用目前勾選的來源，建立表格：

來源 ID｜來源名稱｜來源類型｜可支持的故事事實｜可支持的文化／視覺細節｜文件中記錄的授權或審訂狀態｜不可據此推論的內容｜引用

要求：
- 文件沒寫授權狀態就填「未記錄」，不可自行判定可用。
- 若來源互相矛盾，另列「衝突清單」，不要自行裁決。
- 來源沒有寫到的內容一律標示「待確認」。
- 最後列出開始改編前仍缺少的資料，並按「會阻擋製作／可稍後補」分類。
```

## N02｜原作事件核對

```text
只根據〔故事原文來源名稱〕整理原作事件核對表：

順序｜人物｜做了什麼｜原因｜造成的結果｜不可改動的關鍵台詞或詞語｜來源引用

規則：
- 不得補橋段、改因果或替缺漏合理化。
- 找不到證據時寫「原文未交代」。
- 將「原文事實」和「可能的改編空間」分成兩區。
- 最後指出哪些事件若刪掉，會改變故事核心。
```

## N03｜文化、語言與授權紅線

```text
只依目前勾選來源，找出本繪本中需要特別保護的內容。

請分成：
1. 必須逐字保留的名稱、族語、譯文或關鍵句。
2. 有明確來源支持的服飾、器物、地點、禮俗或歷史細節。
3. 來源只支持特定人物、社群、年代、性別或場合，不能泛化的內容。
4. 來源未說明、不可由 AI 猜測的內容。
5. 文件中記錄的使用、上傳、展示或公開限制。
6. 必須由作者、語言老師、文化知識持有人或權利人確認的項目。

每項輸出：內容｜適用範圍｜來源引用｜目前狀態（已確認／待確認／禁止推論）｜建議確認者。
如果文件沒有授權說明，只能寫「授權未記錄」。
```

## N04｜故事節拍拆解（課後比較練習）

```text
根據已核對的原作事件，把故事拆成下列可能的節拍：設定、觸發、升級、停頓、反應、轉折、高潮、收尾。

每一拍輸出：
- beat_id
- 敘事功能
- 主要人物與動作
- 前一拍如何造成這一拍
- 情緒重量（低／中／高）
- 對白密度（無／少／中／多）
- 必須看見的畫面資訊
- 來源支持或待作者決定
- 來源引用
- 是否需要語言／文化真人確認

先完成節拍，再依節拍重量建議 6、7、8 頁三種分頁方案。
不得先假設固定頁數後硬塞內容，也不得改動紅線清單。
```

## N05｜角色與場景事實表

```text
只使用目前勾選的來源，建立「角色與場景事實表」。這不是自由想像，也不是生圖提示詞。

角色欄位：
角色 ID｜姓名或稱呼｜關係與角色功能｜來源明示的外觀｜來源明示的服裝／配件｜性格與行動證據｜不可變項｜未知項目｜引用

場景欄位：
場景 ID｜地點｜時間｜來源明示的空間與固定物件｜光線／季節證據｜不可新增元素｜未知項目｜引用

要求：
- 圖片來源要說明「畫面看得到什麼」，不要推測看不到的角度。
- 來源沒寫的膚色、服飾名稱、圖紋意義、材料或身分，全部標示「待確認」。
- 最後列出可交給作者自由設計、但需明確標成創作決定的欄位。
```

## N06｜分齡文字核對與改寫建議（課後進階）

```text
請將已核對的故事文字調整成適合〔年齡／閱讀程度〕的版本。

逐段輸出：
原文｜精簡／改寫建議｜改寫理由｜必須保留不動的詞語｜是否改變原意｜來源引用｜需作者確認事項

限制：
- 可以縮短句子與降低難字，但不得改變人物、動作、因果、文化意義及鎖定詞語。
- 可能改變原意的句子只能列為建議，標示「需作者確認」。
- 不新增道德結論或原文沒有的文化解釋。
```

## N07｜NotebookLM Studio 故事樣書／閱讀簡報（課後進階）

這一組只做敘事與閱讀方向樣稿，不直接當出版成品。

```text
請根據目前勾選的故事原文、角色事實表及文化審訂資料，製作一份繁體中文的故事樣書／閱讀簡報初稿。

要求：
- 一頁一個主要故事節拍。
- 不改寫鎖定詞語與關鍵台詞。
- 不新增來源沒有的人物、服飾、器物或文化意義。
- 每頁文字短而可讀，適合〔年齡〕。
- 對來源無法支持的畫面標示「創作決定待作者同意」。
- 本次只檢查敘事與視覺方向，不視為正式出版成品。

以下 YAML 只控制視覺與版面，不是故事事實，也不得改變原作：
〔只貼 `02-visual-system` 中已核准的 `output` 與 `style` 欄位〕
```

重要限制：Google 官方目前說明，Slide Deck 的逐頁修訂不會重新參考 Sources。任何逐頁改字或改圖都可能偏離來源；修改後必須匯出或重新上傳成新版草稿，再做來源核對。介面與功能會更新，上課前以 [Google 官方說明](https://support.google.com/gemininotebook/answer/16757456?hl=en) 為準。

## N08｜把草稿重新上傳後做初步來源核對（課後進階）

先把目前 PDF／PPTX 上傳成來源並命名為 `DRAFT-v01`，再貼：

```text
你是來源核對助手。請比較 DRAFT-v01、故事原文、角色／場景事實表、文化審訂資料及驗收規格。

逐項輸出：
檢查項目｜PASS／FAIL／待真人確認｜草稿證據｜原始來源引用｜最小修正指令

至少檢查：
- 人物、事件順序與因果
- 鎖定名稱、原文與譯文
- 角色與場景固定特徵
- 是否新增來源未支持的文化或歷史主張
- 哪些是合理的創作決定、是否已標示
- 授權或真人審訂狀態是否被誤寫成已完成

任一來源忠實、文化、語言或授權硬條件失敗，整體不得通過初步核對。
不要替草稿找理由，也不要重寫整本；只指出最小必要修正。
```

這只是同一工具內的初步來源比對，不算 Captain 流程中的獨立終驗。正式驗收仍要由不同生成者的同儕／新對話執行，並由真人決定文化、語言、權利與公開狀態。

### NotebookLM 與 YAML 的操作提醒

課堂可要求 NotebookLM 輸出 YAML 程式碼區塊，再複製保存成 `.yaml`。若要把核准 YAML 再放回 NotebookLM 當來源，建議同時保存一份 Markdown／純文字版並寫明版本、審訂者與日期，避免工具對檔案格式的支援差異影響上課。

# B. 聊天機器人：想、寫、規劃

## C00｜先訪談，不急著生故事

```text
你是我的繪本製作訪談助手。先不要寫故事、不要生圖、不要產 YAML。

請一次問我最多 5 個最重要的問題，釐清：
- 讀者年齡與閱讀程度
- 故事核心與希望留下的感受
- 原始來源與我有權使用的範圍
- 哪些事實、語言或文化內容不能改
- 我今天要完成幾頁規劃、幾張完成圖

一次只問必要問題。我沒提供的資料不要替我假設。
等我回答後，先整理成「已知／待確認／不可推論」三區，讓我確認後才進下一步。
```

## C01｜從核准事實包拆節拍，再決定頁數

```text
以下「故事事實包」（可以是核准的 Markdown，或 `00-source-pack` YAML）是目前唯一可確認的內容。你可以提出創作選項，但不得把選項改寫成來源事實。

〔貼上 source-pack.md〕

任務：
1. 先用設定、觸發、升級、停頓、反應、轉折、高潮、收尾拆故事節拍。
2. 每一拍標示：敘事功能、人物動作、因果、情緒重量、對白密度、來源支持／創作提案、需真人確認事項。
3. 若故事適合 6–8 頁，再提出 6、7、8 頁方案並說明合併或拆開哪些節拍；若不適合，必須先說明原因，不可硬塞。
4. 推薦一個最適合〔讀者年齡〕、可在本次課堂執行的方案，由作者選定後才填頁數。

限制：
- 不得更改不可改寫清單。
- 未知內容保留「待確認」。
- 每頁只安排一個主要敘事動作。
- 先等我選定方案，不要直接寫完整內文。
```

## C02｜把白話轉成內容 YAML

```text
你是 YAML 編輯助手。請把我核准的故事事實包、故事節拍與分頁方案填入我提供的 `01-content.template.yaml`。

規則：
- 保留原模板欄位與欄位順序。
- 只輸出一個可解析的 YAML 程式碼區塊，不加前言與結語。
- 字串含冒號、井字號或特殊符號時加引號。
- 不知道的值填 null；需真人確認的值填 status: pending_human_review。
- 每個來源事實填 source_refs；AI 提案填 decision_type: creative_proposal。
- 不改動 locked_text 與 non_negotiables。
- 不新增來源沒有的族語、服飾、歷史、祭儀或人物身分。

輸入資料：
〔貼上事實包、節拍、方案與模板〕
```

## C03｜建立角色、場景與畫風 YAML

```text
根據已通過 Gate 1 的 `N-CLASS` 事實包（課後也可改用 N05 詳細表），以及作者提出的視覺方向，填入 `02-visual-system.template.yaml`。

請分開處理：
1. character_anchors：臉型、髮型、身形比例、服裝、配件、五個不可變特徵。
2. scene_anchors：地點、固定物件、時間、光線、色盤、不可新增元素。
3. style：線條、材質、色盤、人物比例、背景、光影、構圖習慣、避免事項。
4. output：比例、尺寸、檔案格式與文字政策。

規則：
- 來源事實與作者創作決定要分開標示。
- 只看得到正面的參考圖，不得補背面結構。
- 不用「民族風」等模糊詞替代具體證據。
- 不模仿特定在世創作者；改用可觀察的線條、材質、色盤與構圖描述。
- 未確認文化欄位填 null 或 pending_human_review。
- 只輸出一個可解析的 YAML 程式碼區塊。

資料：
〔貼上 N-CLASS 核准內容、作者視覺提案與模板〕
```

## C04｜建立文化與語言紅線 YAML

```text
把 `N-CLASS` 的「不可改寫、待確認、來源與權利」內容填入 `03-culture-guardrails.template.yaml`；課後也可改用 N03 的詳細結果。這是限制卡，不是美術裝飾卡。

- 未完成真人確認時，overall_status 必須是 pending_human_review。
- 只輸出一個可解析的 YAML 程式碼區塊。

已核對資料與模板：
〔貼上 N-CLASS 核准內容及模板〕
```

```text
- 必須看見：〔元素〕
- 不得出現：〔元素〕

- 引用既有 character_id 與 scene_id，不另創造角色或場景。
- 只描述本頁一個主要敘事動作。
- 明確寫 shot_size、camera_angle、subject_position、negative_space。
- 複製文化與語言限制，不自行簡化。
```

```text
你是生圖提示詞組裝員，不是故事作者。

請只根據以下核准資料，組成一份可交給〔生圖工具名稱〕的繁體中文提示詞：

只輸出「正向提示詞」和「負向提示詞」兩區，不解釋。

〔貼上核准資料〕
```

## C07｜開新對話做獨立驗收

這組提示詞要放在另一個新對話，或交給沒有參與生成的同學。

