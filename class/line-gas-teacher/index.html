同一個 LINE BOT，
老師新增、學生查詢

原本的 Code.gs 不必改。另加一個 TeacherForms.gs，同一個 LINE BOT 就能把四份老師專用表單傳給你；老師在 LINE 點連結填寫，學生照常查詢與測驗。資料仍在原本那份試算表。

先看運作方式

同一個 LINE BOT 傳老師表單選單→老師點受限表單→登入填寫→寫進原試算表→學生照常查詢
📅 新增課程

填名稱、時間、地點與可選的提醒時間，寫入「行事曆」。

📚 新增單詞

填中文、族語、例句與可選的 HTTPS 音檔網址，寫入「單詞表」。

💬 新增每日一句

選日期、填句子與翻譯；同一天再次提交會更新當天內容。

🔔 新增通知

填發送時間與內容，勾選「確認發送給已訂閱學生」後排入「通知」；學生機器人的定時程式負責送出。

原本的 Code.gs 一行都不用動。

新增檔案建立表單，並用既有 LINE 權杖把表單選單送到老師自己的聊天室；原本的 Webhook 和學生指令照舊。由於舊 doPost 沒有呼叫教師模組，直接傳「新增課程」不會收到表單；請點機器人送來的選單連結。這個流程不需要付費 AI API。

在原機器人加上老師功能

先完成LINE × GAS 入門版的 setup。以下都在原本與那份試算表連動的 Apps Script 專案操作；不必新增 LINE 官方帳號、Apps Script 專案或第二個 Webhook。

先核對兩個時區。

在原 Google 試算表點「檔案 → 設定」，確認時區是「(GMT+08:00) 台北」；原 Apps Script 的「專案設定」也要選 Asia/Taipei。

  1. 回到原本那份試算表與專案

    開啟學生機器人使用的 Google 試算表，點「擴充功能 → Apps Script」。左側應看到既有的 Code.gs；它已存好同一個 LINE BOT 的 LINE_ACCESS_TOKEN。不要新增另一個權杖。

    完成後會看到：原本七張分頁與機器人程式都在。

  2. 只新增 TeacherForms.gs

    在 Apps Script 左側「檔案」旁點 ＋ → 指令碼，名稱輸入 TeacherForms。把本頁完整教師模組貼到新檔並按 Ctrl+S。不要開啟、覆蓋或修改原本的 Code.gs。

    完成後會看到：左側同時有原本的 Code.gs 與新的 TeacherForms.gs，專案仍只有原本一個 doPost。

  3. 執行 setupTeacher 建立四份表單

    在同一專案的函式選單選 setupTeacher，按「▶ 執行」並完成 Google 授權。程式會沿用原 SPREADSHEET_ID，以目前執行者的 Google 帳號作為老師，建立四份尚未發布的表單和送出觸發器；重跑不應清空既有七張分頁。

    完成後會看到：執行紀錄列出四份表單的編輯連結，原試算表新增「老師表單紀錄」與表單回覆分頁。

  4. 逐份確認只有老師能填，再發布

    開啟四個編輯連結，確認每份表單「一般存取權」為受限制，回覆者只加入老師自己的 Google 帳號；「收集電子郵件地址」選已驗證，不要開「每人只能回覆一次」或公開回覆摘要。確認後才發布，並用未授權的另一個 Google 帳號試開填寫連結，應無法填答。

    完成後會看到：老師可填，其他帳號即使拿到表單網址也沒有填答權限。

  5. 從「學生」分頁找到自己的 LINE ID

    老師用自己的 LINE 帳號，在原本同一個機器人傳 訂閱。回原試算表的「學生」分頁，依剛剛的加入或更新時間辨認自己那列，複製 A 欄以 U 開頭的完整 ID。到 Apps Script 左側「專案設定 → 指令碼屬性」新增 TEACHER_LINE_USER_ID，值貼這個 ID 並儲存；原本的 LINE_ACCESS_TOKEN 不必改。若同時有多人操作，先比對時間，無法確定是哪列就不要猜。老師若不想接收學生通知，取得 ID 後可傳 取消訂閱；A 欄 ID 仍會保留。

    完成後會看到：原指令碼屬性多了老師 ID；學生資料表不必新增欄位。

  6. 啟用教師表單並檢查

    回同一專案依序執行 enableTeacherLinks、checkTeacherSetup。後者會檢查原本的 LINE 權杖、老師 ID、時區、試算表與表單。教師表單存取權和 Email 的介面選項仍須以前一步的人工核對為準。

    完成後會看到：執行紀錄顯示教師表單可用。

  7. 執行 sendTeacherMenu，把選單傳到自己的 LINE

    在 Apps Script 上方的函式選單選 sendTeacherMenu，按「▶ 執行」。它會使用原本那一個 LINE BOT，把四份表單的填寫連結傳給老師 ID；LINE 端可以把這則訊息釘選或收藏。下次需要重新取得連結，再執行一次此函式即可。

    完成後會看到：老師和學生都仍在同一個 BOT 聊天；只有老師自己的 LINE 收到教師表單選單。

  8. 從 LINE 點表單，測試老師與學生

    老師從剛收到的選單點「新增課程」，用自己的 Google 帳號填一筆未來課程。回原試算表確認「行事曆」增加一列；學生在同一個 BOT 傳 行事曆，應能看到新課程。再用未授權的另一個 Google 帳號試開表單連結，應無法填寫。

    完成後會看到：老師從同一個 LINE BOT 的訊息進入表單，學生原有指令照常使用。

如果先前照舊版建了另一個老師專案：

這頁的新檔要加在學生機器人原本的專案。若舊專案卡在「這個表單目前沒有回覆目標」，那份尚未發布的草稿表單可先不動；不要把舊老師程式整份貼進原專案，也不要為它新增第二個 Webhook。若舊表單已有人填答或舊觸發器已運作，請先確認資料與觸發器狀況，再搬移或停用，避免重複寫入。

老師在同一個 LINE BOT 怎麼用？

先按一次 sendTeacherMenu在 Apps Script 執行，讓原本的機器人私訊表單選單。
📅 新增課程點選單裡的課表連結。
📚 新增單詞點選單裡的單詞連結。
💬 新增每日一句點選單裡的句子連結。
🔔 新增通知點選單裡的通知連結；到時間才會推播。
再取一次選單回 Apps Script 再執行一次 sendTeacherMenu。

原本的學生指令照舊。這個「只加一個檔案」版本不支援老師直接傳「新增課程」取得回覆；若要這種文字指令，原本的 Webhook 程式必須另加指令分流。表單送出後以原試算表實際新增或更新的資料為準。

表單送出後，去哪裡看？

填寫表單原試算表的正式資料分頁學生端看到什麼
新增課程行事曆學生傳「行事曆」看到最近的未來課程；有提醒時間時由學生端定時程式處理。
新增單詞單詞表學生傳「單詞表」或「查單詞 關鍵字」。
新增每日一句每日一句日期等於台灣今天時，學生傳「每日一句」可看到。
新增通知通知到發送時間後，學生端的 sendDueNotifications 觸發器向已訂閱帳號推播。
表單原始回覆也會在同一份試算表。

那些新增的「表單回應」分頁是備份；同一個機器人讀的是正式的「行事曆」「單詞表」「每日一句」「通知」分頁。通知不會在老師按下送出表單的瞬間立即發送，仍以既有定時觸發器為準。

要現在發給學生？另加一個 .gs 檔就好

老師在 LINE 送出「新增通知」表單後，資料會先進原試算表的「通知」分頁，按原排程時間送出。若要立刻發送，可以在原試算表加一個獨立的 ImmediateSend.gs，選取那筆通知後點「LINE 通知 → 立即發送選取的通知」，核對內容和待發送人數再確認。

仍使用同一個 Apps Script 專案。

ImmediateSend.gs 也加在原試算表的 Apps Script，沿用同一個 LINE BOT 的權杖。點發送時會把通知的「發送時間」改成現在，每次最多嘗試 20 位；再次點擊時，程式會跳過「發送紀錄」中已有成功紀錄的對象。

權限與限制

  • 四份 Google 表單必須只開放老師帳號回覆；表單網址不是密碼，所以不能設成「知道連結的人都能回覆」。
  • 老師和學生在同一個 LINE BOT。程式只把選單私訊到 TEACHER_LINE_USER_ID；LINE 訊息可能被轉傳，真正的寫入限制是 Google 表單的受限帳號與已驗證 Email。
  • 四份表單的原始回覆也會存進同一份試算表，其中可能有老師的電子郵件；試算表本身請維持老師管理，不要開放學生瀏覽或編輯。
  • 「行事曆」是試算表課表，不會同步 Google Calendar。要改課程時間或取消課程，先到原試算表修改；這版表單只處理新增，當日句子例外可覆寫同一天資料。
  • 同一專案只保存一份 LINE_ACCESS_TOKEN。教師 LINE ID 也只放在指令碼屬性；不要把權杖、學生名單或實際表單連結貼進公開教材。
  • 請先用測試帳號與假資料驗收。這份程式沒有生成式 AI 對話，也不會憑空產生族語內容；族語拼寫與翻譯仍由老師確認。

卡住時先看這裡

老師的 LINE 沒收到表單選單？

確認老師 LINE 帳號已加原機器人好友；在原試算表「學生」分頁核對自己的 ID，並確認 TEACHER_LINE_USER_ID 完整無空格。重新執行 checkTeacherSetup、sendTeacherMenu，查看 Apps Script「執行項目」有沒有 LINE API 錯誤。新增教師檔不需要重新部署原 Webhook。

LINE 有表單連結，但表單說無法存取？

確認目前登入的是被加入「回覆者」的老師 Google 帳號，並確認該表單已發布。若你同時登入多個 Google 帳號，可先切到正確帳號。

表單送出了，LINE 查不到新課程？

先看原試算表「行事曆」有沒有新列，時間是否在未來、啟用是否為「是」。若只在原始表單回應分頁找到資料，請看同一 Apps Script 的「執行項目」中 teacherFormSubmit 是否報錯。

新增通知後沒有推播？

確認同一專案已執行 installTrigger、目標學生傳過「訂閱」、通知時間已到且在有效範圍內；查看原試算表「發送紀錄」與 Apps Script「執行項目」。

傳「新增課程」後，機器人沒有給表單？

這是只新增一個檔案、完全不改原 Code.gs 的限制。請點 sendTeacherMenu 傳到 LINE 的選單連結；原本的 doPost 不會自動辨識新檔裡的教師指令。

執行 setupTeacher 出現「這個表單目前沒有回覆目標」？

舊版程式太早呼叫 getDestinationId()，新表單尚未連接試算表就會拋錯。如果你目前跑的是舊老師專案的 程式碼.gs，網站更新不會自動更改該專案。請回到學生機器人的原試算表，新增本頁修正版 TeacherForms.gs 後才執行它的 setupTeacher；如果原專案已經有這份新檔，儲存新版後重跑即可，會沿用前次建立的表單。
