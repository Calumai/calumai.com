給已完成 LINE × GAS 入門版的老師

直接在 LINE 說，
資料就進試算表

老師在同一個 LINE BOT 傳「新增行事曆／新增課表」「新增單詞」「新增每日一句」「新增題目」或「新增通知」。機器人先問通行碼，再逐題詢問資料；最後核對並點「確認新增」，資料就進原本那一份 Google 試算表。

LINE 裡完成不用開四份 Google 表單，不用切到試算表輸入。沿用原 BOT、原 Apps Script 專案、原試算表與原 Webhook 網址。
本頁目錄它怎麼運作安裝步驟LINE 指令示例資料去哪裡立即發送通知權限與限制卡住時TeacherLine.gs

一個 BOT，老師新增、學生查詢

老師在 LINE 傳新增指令→輸入通行碼→逐題填資料→核對並點確認新增→原試算表新增資料
📅 新增行事曆／課表

在對話中填課程名稱、日期時間、地點等，寫入試算表「行事曆」。「新增課程」也可使用。

📚 新增單詞

填中文、族語、例句與可選音檔，寫入「單詞表」。

💬 新增每日一句

填日期、族語句子、中文翻譯，寫入「每日一句」。

📝 新增題目

填題目、A/B/C 選項、正解和可選解說，寫入「題庫」。「新增測驗題」也可使用。

🔔 新增通知

填發送時間和內容，寫入「通知」；到時間後依原本的定時觸發器發送。

原本 Code.gs 要做一小處接線。

舊版「只加一個 .gs、不改 Code.gs」無法讓原本的 Webhook 辨識老師的新指令。這次新增 TeacherLine.gs，在原本的 command_ 開頭接上老師指令；不用重做 BOT，也不會多一個 doPost。

從原本的學生機器人加上老師功能

先完成LINE × GAS 入門版：原試算表已有七個分頁，setup 跑過，學生傳「說明」會有回覆。下面都在同一份試算表連動的 Apps Script 專案操作。

  1. 新增 TeacherLine.gs

    從原試算表點「擴充功能 → Apps Script」。編輯器左側「檔案」旁點 ＋ → 指令碼，名稱輸入 TeacherLine。點本頁「複製完整 TeacherLine.gs」，貼進新檔，按 Ctrl+S 儲存。原有的 Code.gs 請保留。

    完成後會看到：檔案清單同時有 Code.gs 與 TeacherLine.gs。

  2. 在原 Code.gs 接上老師指令

    開啟 Code.gs，搜尋 function command_(text, uid) {。在這個大括號下一行、原本第一個 if 前面貼入下面這一小段；其餘學生指令原樣保留。如果你的程式已經有這段，就不用重複貼：

      if (text === '我的ID') return '你的 LINE 使用者 ID：' + uid;
  if (typeof teacherLineCommand_ === 'function') {
    const teacherAnswer = teacherLineCommand_(text, uid);
    if (teacherAnswer !== null) return teacherAnswer;
  }

    只貼框內這幾行，不要另外增加第二個 command_ 或 doPost。按 Ctrl+S。本網站入門版的新 Code.gs 已含這段接線；先前複製到自己 GAS 的舊版仍要手動補上。

    完成後會看到：專案儲存成功，原本的 doPost 仍只有一個。

  3. 更新原本的網頁應用程式部署

    程式改了之後，到 Apps Script 右上角點「部署 → 管理部署作業」，在原本的網頁應用程式旁點鉛筆，版本選「新版本」，按「部署」。如出現授權畫面，照畫面完成。這是更新原部署，不是新增第二個部署；LINE Developers 的 Webhook URL 保持原本的 /exec 網址。

    完成後會看到：原部署顯示新版本，Webhook URL 不必重貼。

  4. 在 LINE 取得自己的 ID

    用老師自己的 LINE，向同一個 BOT 傳 我的ID。機器人會回你自己的 U... ID。複製完整一串；這個 ID 是 LINE 的使用者 ID，與 Google 試算表 ID 不同。

    完成後會看到：BOT 回覆老師自己的 LINE ID。

  5. 設定老師 ID 與通行碼

    回 Apps Script 左側「專案設定」齒輪，在「指令碼屬性」新增兩筆：TEACHER_LINE_USER_ID 貼剛剛取得的完整 ID；TEACHER_PASSCODE 設定老師自己記得的通行碼，至少 8 個字元。1234 只是示意，不要真的使用。按儲存。原有的 LINE_ACCESS_TOKEN 和 SPREADSHEET_ID 保留。

    完成後會看到：指令碼屬性多了老師 ID 和通行碼兩筆。

  6. 用老師 LINE 實測一筆

    在同一個 BOT 傳 新增單詞。機器人先問通行碼，輸入剛剛設定的值；正確後跟著問題逐一填資料。最後核對摘要，點 LINE 裡的「確認新增」；回原試算表「單詞表」確認多了一列。學生再傳 查單詞 關鍵字，確認能讀到新資料。輸入過程想停，可傳 取消。

    完成後會看到：老師在 LINE 輸入資料並確認，原試算表新增一列，學生原本指令正常。

想立刻發通知？

LINE 的「新增通知」是建立預定時間的通知，到時間再發。若要當下就發，可用獨立的 ImmediateSend.gs：在原試算表選取通知資料列，點「LINE 通知 → 立即發送選取的通知」，核對內容與待發人數後確認。

權限與限制

  • TEACHER_LINE_USER_ID 請填老師自己的完整 LINE 使用者 ID，TEACHER_PASSCODE 至少 8 字元；設定值放在指令碼屬性，不寫進公開程式。請使用專用通行碼，因為你輸入的內容仍會留在 LINE 聊天紀錄。
  • Apps Script 網頁應用程式讀不到 LINE 的 X-Line-Signature 標頭，不能驗證 Webhook 真的來自 LINE。老師 ID、通行碼與回到老師 LINE 的確認步驟能降低誤寫或冒用，仍不等於完整的來源驗證；請勿拿來處理敏感資料。
  • 試算表請維持只有老師能編輯；不要把 LINE_ACCESS_TOKEN、學生名單或其他私人資料貼到公開教材。
  • 單詞與每日一句的族語內容要由老師自行審核。先用測試資料走完一次，再輸入正式教材。

卡住時先看這裡

傳「新增單詞」沒有反應？

先確認學生原有的「說明」是否有回覆。若有，檢查 Code.gs 的 command_ 開頭是否已加上本頁的接線程式，再到「部署 → 管理部署作業」確認原部署已選新版本。只按 Ctrl+S 不會更新已發布的 /exec 版本。

機器人說我不是老師？

確認是用老師自己的 LINE 帳號傳訊，並在 Apps Script「專案設定 → 指令碼屬性」核對 TEACHER_LINE_USER_ID。要貼完整的 U...，不能貼 Google 試算表 ID 或 LINE 顯示名稱。

通行碼忘記了或一直被拒絕？

到 Apps Script「專案設定 → 指令碼屬性」查看或更新 TEACHER_PASSCODE，至少 8 字元。不要把通行碼貼給學生；連續錯誤 5 次會暫停約 10 分鐘。

連續新增第二筆，沒有立刻收到確認按鈕？

為避免重複推送，確認卡之間至少間隔 30 秒。請等一下，再在同一個 LINE 對話傳 送出；收到摘要後核對並按「確認新增」。

按確認後，試算表沒有新增？

檢查 Apps Script 左側「執行項目」中的最新 doPost。確認你開的是原本那份試算表、setup 已完成，並核對該分頁第一列欄名沒有被改掉。

新增通知後學生沒收到？

這不是立即發送。確認發送時間已到、原專案執行過 installTrigger、學生傳過「訂閱」；再看原試算表「發送紀錄」與 Apps Script「執行項目」。

之前建過四份老師表單，現在還要用嗎？

這套 LINE 對話版不需要 setupTeacher、四份 Google 表單，也不需要逐份發布。若舊表單已有實際回覆或觸發器，先確認那些資料與觸發器的用途，再決定是否停用；不要直接刪除既有資料。
